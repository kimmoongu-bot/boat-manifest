# Korean Mobile UI

frontend-design 스킬이 "어떻게 개성 있게 만들까"를 다룬다면, 이 스킬은 "이 사용자의 앱에서 절대 어기면 안 되는 것"을 다룬다. 두 스킬을 같이 읽고 작업한다.

## 1. 사용자와 환경을 먼저 정한다
- 현장용 앱(챙김, 업무노트, 현장관리, TripNote): 사용자는 장갑 낀 손, 햇빛 아래, 한 손 조작. **정보 밀도보다 오조작 방지**가 우선.
- 소비자용 앱(패밀리노트, 잠김/Kepta, PawsDay, KORIVU): 첫인상이 곧 설치/이탈. **첫 화면 하나에 앱의 성격이 드러나야** 한다.
- 둘 중 어느 쪽인지 코드/파일명에서 판단이 안 되면 작업 전에 한 줄로 확인한다.

## 2. 한글 타이포그래피 (가장 자주 틀리는 부분)
- 본문 폰트: `Pretendard Variable` → 없으면 `Pretendard` → `-apple-system, "Apple SD Gothic Neo", "Noto Sans KR", "Malgun Gothic", sans-serif`. CDN은 `https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/variable/pretendardvariable-dynamic-subset.min.css`.
- 영문 서체(Inter, Roboto 등)만 지정하고 한글을 시스템 fallback에 맡기지 않는다. 한글이 굵기·자간이 달라 보이면 그 이유다.
- 본문 최소 15px(현장용 16px), `line-height: 1.6`, `letter-spacing: -0.01em ~ -0.02em`. 한글은 자간을 살짝 좁혀야 단정해진다.
- `word-break: keep-all` 필수. 한글 단어가 줄 끝에서 끊기지 않게 한다.
- 제목은 굵기(700)로 구분하고 크기는 2단계(예: 22/18)까지만. 굵기 400·500·700 외에는 쓰지 않는다.
- 숫자(금액·시간·계측값)는 `font-variant-numeric: tabular-nums`로 자릿수를 맞춘다.

## 3. 터치와 레이아웃
- 탭 대상 최소 44×44px, 현장용은 48px 이상. 버튼 사이 간격 8px 이상.
- 주요 동작 버튼은 **화면 하단 고정**(엄지 영역). 상단 우측 아이콘 하나에 핵심 기능을 숨기지 않는다.
- 간격은 4px 배수(4/8/12/16/24/32)만. 임의 값(13px, 18px) 금지.
- 좌우 여백 16px, 카드 안쪽 여백 16px, 카드 모서리 12px(현장용) / 16px(소비자용). 한 앱 안에서 모서리 값은 하나로 통일.
- 한 화면에 카드 스타일은 1종, 버튼 스타일은 primary/secondary/ghost 3종까지.
- 리스트는 구분선보다 간격(12~16px)으로 나누다. 구분선을 쓰면 `1px solid` + 매우 옅은 색.

## 4. 색
- 토큰으로만 쓴다: `--bg`, `--surface`, `--text`, `--text-muted`, `--border`, `--primary`, `--danger`, `--success`. 하드코딩 hex를 컴포넌트에 직접 넣지 않는다.
- 다크 테마가 기본인 앱(패밀리노트 등)은 순수 검정 `#000` 대신 `#0F1115`~`#141518`, 표면은 한 단계 밝게(`#1C1E24`). 텍스트는 `#FFFFFF`가 아니라 `#E8E8EA`.
- 포인트 색은 **하나**. 보조 색은 포인트 색의 명도 변형으로 만든다. 그라데이션 배경은 기본값으로 쓰지 않는다.
- 상태색(danger/success/warning)은 텍스트+아이콘을 같이 써서 색만으로 의미를 전달하지 않는다.
- 대비: 본문 4.5:1, 큰 글씨 3:1 이상. 야외용은 더 높게.

## 5. 현장용 앱 추가 규칙
- 입력은 타이핑보다 선택(칩, 세그먼트, 피커)으로. 자주 쓰는 값은 최근 사용 순으로 상단에.
- 저장 버튼은 항상 보이고, 저장 결과를 토스트로 1.5초 표시. 저장 실패는 화면에 남겨둔다.
- 오프라인 상태를 상단 띠로 표시하고 큐에 쌓인 건수를 보여준다.
- 서명·사진 첨부 영역은 최소 높이 160px, 테두리 점선으로 "여기 눌러 추가" 문구.
- 표는 모바일에서 카드로 변환한다. 가로 스크롤 표 금지.

## 6. 소비자용 앱 추가 규칙
- 첫 화면에 빈 상태(empty state)를 반드시 디자인한다: 짧은 한 문장 + 주요 동작 버튼 1개. "데이터가 없습니다" 금지.
- 온보딩은 3화면 이하. 권한 요청은 그 기능을 처음 쓸 때.
- 앱 이름·아이콘·포인트 색이 한 세트로 보여야 한다. 스토어 스크린샷에서 그대로 쓸 수 있게.

## 7. UX 카피
- 버튼은 동사로 끝나는 짧은 명령형: "저장", "기록 추가", "사진 올리기". "확인/취소"만 있는 대화상자는 무엇을 확인하는지 제목에 쓴다.
- 오류 문구는 "무엇이 잘못됐고 → 어떻게 하면 되는지" 두 부분. 기술 용어(null, 500, token) 노출 금지.
- 존댓말 통일: "~하세요/~됩니다". 한 앱 안에서 반말·존댓말 섞지 않는다.
- 날짜는 `2026.10.15 (목)`, 시간은 `09:40`, 금액은 `12,000원`. 한국식 표기 외 혼용 금지.

## 8. 작업 절차
1. 대상 화면과 사용자(현장/소비자)를 한 줄로 적는다.
2. 기존 코드의 토큰·폰트·간격 체계를 먼저 찾아 그대로 따른다. 없으면 위 규칙으로 `:root` 토큰부터 만든다.
3. 화면 하나를 끝까지 완성한 뒤 다음 화면으로 간다. 여러 화면을 반쯤 고쳐두지 않는다.
4. 끝나면 Browser 패널 또는 스크린샷으로 **375px 폭**에서 확인하고, 한글 줄바꿈·버튼 크기·대비를 점검한다.
5. 바꾼 디자인 결정(폰트, 토큰, 간격)은 프로젝트 CLAUDE.md의 "디자인" 섹션에 3줄 이내로 기록해 다음 세션이 같은 규칙을 쓰게 한다.
